DOCUMENTATION

How BOTPass works

The main flow, organized in the same order as the product menu.

01

Events

Browse the latest 100 events stored in the BOTPass contract. Opening an event shows its organizer, schedule, claim status, and total pass count.

02

Create

Connect an organizer wallet, add the event details and dates, then confirm one transaction. The event is created with claims closed.

03

Manage

The organizer opens claims when attendees may join and closes them when claiming should stop. Only that event’s organizer can change this switch.

04

Open Claim

An attendee opens the event, connects a wallet, and confirms one claim transaction. Each wallet can claim an event only once.

05

My Passes

BOTPass scans the latest 100 events and lists every event the connected wallet has claimed, including the on-chain claim time.

06

Verify

Anyone can check an event ID and wallet address. A timestamp means the claim exists; zero means that wallet has not claimed that event.

Open Claim vs. the removed QR flow

Open Claim uses no signed QR session. It is cheaper and simpler: the organizer controls one open/closed switch, while the contract still prevents duplicate claims.
